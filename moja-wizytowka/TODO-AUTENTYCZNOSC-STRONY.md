# TODO — autentyczność strony i ograniczenie „AI slopu”

Aktualizacja: 20 lipca 2026 r.

Cel: zachować czytelność i jakość techniczną strony, ale nadać jej bardziej
osobisty, wiarygodny charakter. Strona nie powinna wyglądać jak uniwersalny
szablon agencji ani zawierać faktów, obietnic lub wyników wymyślonych na potrzeby
marketingu.

## Zasady pracy

- [ ] Każdą liczbę, termin, godzinę obsługi i obietnicę powiązać z rzeczywistą
  decyzją lub źródłem.
- [ ] Nie wymyślać klientów, opinii, rezultatów, stażu, certyfikatów ani liczby
  realizacji.
- [ ] Dema opisywać wprost jako projekty demonstracyjne, a nie wykonane zlecenia.
- [ ] Nie dodawać zdjęcia, profilu zawodowego ani danych osobistych bez świadomej
  decyzji właściciela strony.
- [ ] Nie zmieniać całej strony naraz. Po każdym etapie porównać wersję przed i po.

## P0 — fakty i obietnice do potwierdzenia

- [ ] Potwierdzić, czy deklaracja „od około roku” jest nadal prawdziwa i czy ma
  pozostać na stronie.
- [ ] Potwierdzić realność terminu realizacji „od 3 do 21 dni”. Jeśli nie jest to
  stała zasada, zastąpić go informacją, że termin wynika z wyceny i zakresu.
- [ ] Potwierdzić możliwość odpowiadania na wiadomości w ciągu 24 godzin.
- [ ] Potwierdzić godziny obsługi `pon.–pt. 10:00–18:00`.
- [ ] Potwierdzić zobowiązanie do rozpoczęcia pracy nad zgłoszeniem najpóźniej w
  ciągu dwóch dni roboczych.
- [ ] Potwierdzić zasadę płatności dopiero po zakończeniu uzgodnionych prac.
- [ ] Zapisać źródło i datę potwierdzenia powyższych zasad w dokumentacji.

## P1 — przepisać sekcję „O mnie”

- [ ] Zastąpić nagłówek „Tworzę z pasji. Uczę się przy każdym projekcie” zdaniem,
  które opisuje konkretną cechę Mikołaja albo jego rzeczywisty sposób pracy.
- [ ] Usunąć powtórzenie zwrotu „z pasji” z nagłówka i pierwszego akapitu.
- [ ] Zebrać 2–3 prawdziwe informacje osobiste, na przykład:

  - dlaczego powstała pierwsza strona;
  - jaki problem Mikołaj najbardziej lubi rozwiązywać;
  - które części projektu wykonuje samodzielnie;
  - dlaczego pracuje dla małych firm;
  - co konkretnie sprawdza przed oddaniem strony.

- [ ] Na podstawie potwierdzonych odpowiedzi napisać krótki akapit, którego nie da
  się bez zmian wkleić na stronę dowolnego freelancera.
- [ ] Zdecydować, czy karta autora ma pokazywać logo, prawdziwe zdjęcie, zdjęcie
  stanowiska pracy czy sam tekst. Nie używać przypadkowego zdjęcia stockowego.
- [ ] Usunąć z karty autora dane, które tylko powtarzają nagłówek lub sekcję
  kontaktową i nie budują zaufania.

## P1 — dodać rzeczywisty dowód pracy

- [ ] Zdecydować, czy strona może już prezentować projekty z katalogu
  `../dema stron/`.
- [ ] Wybrać najwyżej 2–3 najlepsze dema zamiast pokazywać wszystkie.
- [ ] Każde demo oznaczyć wyraźnie jako „projekt demonstracyjny”.
- [ ] Przy każdym demie podać tylko fakty możliwe do sprawdzenia:

  - branża i cel projektu;
  - elementy wykonane przez Mikołaja;
  - zastosowane testy lub ograniczenia techniczne;
  - informacja, że projekt nie jest realizacją dla klienta, jeżeli nim nie jest.

- [ ] Nie dodawać fikcyjnych wyników typu „więcej klientów”, „wzrost konwersji” ani
  „szybsza sprzedaż”.
- [ ] Dodać screenshoty dopiero po sprawdzeniu praw do wszystkich wykorzystanych
  grafik i danych.
- [ ] Jeżeli sekcja z dowodami nie powstanie, zmienić podpis „Oferta → dowód →
  kontakt”, ponieważ obecna strona nie pokazuje jeszcze dowodu realizacji.

## P2 — ograniczyć szablonowy styl wizualny

- [ ] Zrobić inwentaryzację powtarzalnych ozdobników:

  - pigułkowe etykiety nad nagłówkami;
  - numerowane separatory sekcji;
  - kropkowane tła;
  - pływające i obrócone karty;
  - duże nagłówki z kolorowym fragmentem;
  - przeplatanie jasnych i ciemnych sekcji.

- [ ] Wybrać 2–3 motywy jako charakterystyczne dla strony, a pozostałe uprościć.
- [ ] Sprawdzić, czy pływające karty „Hierarchia” i „Kontakt” przekazują ważną
  informację. Jeśli są wyłącznie dekoracją, usunąć je.
- [ ] Ograniczyć liczbę elementów obróconych i animowanych.
- [ ] Sprawdzić, czy granatowe logo wizualnie pasuje do pomarańczowo-czarnego
  interfejsu na jasnym i ciemnym tle.
- [ ] Zachować własną ilustrację liniową, jeżeli po uproszczeniu nadal wspiera
  komunikat strony.

## P2 — odchudzić i skonkretyzować tekst

- [ ] Wyszukać wszystkie powtórzenia zwrotów „prosta droga do kontaktu”, „treść
  przed ozdobą”, „najpierw” i „potem”.
- [ ] Pozostawić każde główne hasło najwyżej w jednym miejscu.
- [ ] Zastąpić ogólne przymiotniki „lekka”, „nowoczesna”, „jasna” i „prosta”

- [ ] Skrócić zdania, które jednocześnie opisują zakres, wyjątki i warunki umowy.
- [ ] Sprawdzić, czy sekcja „Standard” wnosi nowe informacje zamiast powtarzać hero
  i usługi.
- [ ] Przeczytać wszystkie nagłówki bez akapitów i usunąć nadmiar konstrukcji
  „krótkie zdanie. drugie krótkie zdanie”.
- [ ] Przeczytać sam tekst bez CSS i sprawdzić, czy nadal brzmi jak wypowiedź jednej
  konkretnej osoby.

## P3 — test wiarygodności i odbioru

- [ ] Pokazać stronę co najmniej trzem osobom, które nie znają projektu.
- [ ] Po pięciu sekundach zapytać każdą osobę:

  - kto oferuje usługę;
  - dla kogo powstają strony;
  - co wyróżnia wykonawcę;
  - który element wygląda generycznie lub sztucznie;
  - czy zaufałaby formularzowi i dlaczego.

- [ ] Zapisać odpowiedzi bez podpowiadania i poprawić elementy wskazane przez co
  najmniej dwie osoby.
- [ ] Sprawdzić ręcznie widoki 320, 375, 768, 1024 i 1440 px.
- [ ] Sprawdzić stronę bez JavaScriptu oraz z `prefers-reduced-motion`.
- [ ] Sprawdzić obsługę klawiaturą, fokus, formularz i kontrast.

## Weryfikacja techniczna po zmianach

Uruchomić rzeczywiście, nie przepisywać wyników ze starszego raportu:

```powershell
npm.cmd run check
npm.cmd run qa
npm.cmd run stability
npm.cmd audit
```

- [ ] Porównać produkcyjny HTML i wygląd z wersją lokalną.
- [ ] Potwierdzić brak błędów konsoli i niedziałających zasobów.
- [ ] Zaktualizować raport tylko rzeczywistymi wynikami z bieżącego uruchomienia.
- [ ] Jawnie zapisać kontrole, których nie udało się wykonać.

## Definicja ukończenia

Zadanie jest zakończone, gdy:

- [ ] sekcja „O mnie” zawiera konkretne, potwierdzone informacje;
- [ ] strona pokazuje prawdziwy dowód pracy albo nie obiecuje, że taki dowód już
  zawiera;
- [ ] żadna liczba i obietnica nie pozostaje bez potwierdzenia;
- [ ] ograniczono liczbę typowych ozdobników landing page;
- [ ] tekst nie powtarza tych samych haseł w kilku sekcjach;
- [ ] osoby testujące potrafią wskazać coś charakterystycznego wyłącznie dla
  Mikołaja;
- [ ] wszystkie obowiązkowe testy przechodzą, a niewykonane kontrole są opisane.
